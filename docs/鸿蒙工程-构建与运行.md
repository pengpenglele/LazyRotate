# 鸿蒙工程构建与运行（HarmonyOS 7 / API 26）

> 工程位置：[harmony/LazyRotate](../harmony/LazyRotate)
> 能力边界见：[鸿蒙版-可行性评估](鸿蒙版-可行性评估.md)
> 本文回答三件事：怎么在本机构建、怎么装到平板、怎么验证它真的按设计工作。

## 0. 先说清楚

- 本工程是 **public SDK 工程**：只使用普通三方应用可用的接口，**不包含** `screen.*` 等系统接口。
- 本工程交付前**没有安装 DevEco Studio / HarmonyOS SDK**，所以**没有真机编译**，
  只做了配置与源码的静态校验（见 [静态校验报告](鸿蒙工程-静态校验报告.md)）。
- 如果 DevEco 打开时有版本字段告警，按第 5 节处理，不需要改业务代码。

## 1. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| DevEco Studio | **能选择 HarmonyOS 7（API 26）SDK 的版本**（2026 年的 26.0.0 版本线；若你的 IDE 显示 6.x/7.x 版本号，以能否选到 API 26 为准） | 版本命名在不同渠道有分歧，见第 5 节兜底 |
| HarmonyOS SDK | **API 26**（`7.0.0(26)`） | Settings > SDK 中安装 |
| 设备 | 鸿蒙 7 平板/手机 | 需要开发者模式 + USB 调试；模拟器对旋转/传感器支持有限，**建议真机** |
| 华为账号 | 用于自动签名 | DevEco 自动签名需登录 |

工程配置（`build-profile.json5`）：

- `compatibleSdkVersion = 7.0.0(26)`：只支持鸿蒙 7+，因为用了 API 26 的 `settings.openDisplaySettingsPage`；
- `runtimeOS = HarmonyOS`；
- 无三方依赖（`oh-package.json5` 为空），不引入任何网络/权限库。

## 2. 打开与同步

1. DevEco Studio → **File > Open** → 选择 `harmony/LazyRotate`；
2. 首次打开等待 **Sync** 完成（会校验 SDK、生成 `.hvigor`/`oh_modules`）；
3. 打开 **File > Project Structure > Project**，确认：
   - `compatibleSdkVersion` = `7.0.0(26)`；
   - `runtimeOS` = `HarmonyOS`。
4. 若 SDK 未下载：**Settings > SDK > HarmonyOS**，安装 API 26。

## 3. 签名（不签名不能安装）

1. **File > Project Structure > Signing Configs**；
2. 勾选 **Automatically generate signature**（需登录华为账号）；
3. 等待自动生成 `default` 签名配置（会写回 `build-profile.json5` 的 `signingConfigs`）。

> 正式分发需要 AGC 中申请发布证书与 profile，并手动配置 release 签名；本文只覆盖自用调试签名。
> **系统签名（全局锁定）不在本文范围**，见可行性评估第 4 节。

## 4. 运行

- 直接点 **Run**（或 `Shift+F10`），选择设备；
- 或者构建 HAP 后用 hdc 安装：

```powershell
# 构建（DevEco 菜单 Build > Build Hap(s)/APP(s) > Build Hap(s)）后：
hdc list targets
hdc install -r entry\build\default\outputs\default\entry-default-signed.hap
hdc shell aa start -a EntryAbility -b com.lazyrotate.app
```

外部指令（与安卓版 `am start` 对齐）：

```powershell
# 指定方向：portrait / landscape / portrait_inverted / landscape_inverted / auto
hdc shell aa start -a EntryAbility -b com.lazyrotate.app ^
  -A com.lazyrotate.app.action.SET_ROTATION --ps target landscape

# 翻转 180°
hdc shell aa start -a EntryAbility -b com.lazyrotate.app ^
  -A com.lazyrotate.app.action.FLIP

# 交还系统
hdc shell aa start -a EntryAbility -b com.lazyrotate.app ^
  -A com.lazyrotate.app.action.FOLLOW_SYSTEM
```

> 注意：`--ps` 的字符串值不能以中划线开头（aa 工具限制）。
> 指令最终只作用于**本应用窗口**；应用不在前台时先被拉起，再在 `onPageShow` 消费指令。
>
> 本工程只保证**显式拉起**（同时给 `-b`、`-a` 与 `-A`）能生效：`-A` 在 aa 工具里属于隐式启动语法组，
> 「显式启动 + action」能否原样进入 `Want.action` 需要真机确认（见静态校验报告 WARN-15）。
> 若真机上 action 没送达，可改用参数形式（`--ps command flip`）并在 `RotationCommand.ets` 里扩展解析。

## 5. 配置版本兜底（DevEco 报 modelVersion / hvigorVersion / compatibleSdkVersion 不匹配时）

DevEco 26 的工程模板字段（`modelVersion`、`hvigorVersion`、`@ohos/hvigor-ohos-plugin` 版本）会随 IDE 小版本变化。
本工程的配置按「API 26 项目」写成 **`modelVersion 6.0.0` / `hvigorVersion 6.0.0`**，如果 IDE 提示不匹配，按下面任一方案处理：

**方案 A（首选，改动最小）**

1. 按 IDE 提示点击 **Migrate**；或
2. 把根 `oh-package.json5` 的 `modelVersion` 改成 IDE 提示的值（例如 `7.0.0`）；
3. 把 `hvigor/hvigor-config.json5` 的 `hvigorVersion` 与 `@ohos/hvigor-ohos-plugin` 改成同一版本；
4. 重新 Sync。

**方案 B（最稳，推荐给第一次接触鸿蒙的同事）**

1. 在 DevEco 26 里新建一个 **Empty Ability** 工程（模板选 API 26，设备类型勾 Tablet）；
2. 把本工程的这些内容覆盖过去：
   - `AppScope/app.json5` 与 `AppScope/resources/`；
   - `entry/src/main/module.json5`；
   - `entry/src/main/ets/` 整个目录；
   - `entry/src/main/resources/` 整个目录；
3. 新工程模板自带的签名、hvigor 版本、`build-profile.json5` 都保留不动；
4. Sync 后 Run。

> 方案 B 不会丢功能：业务代码全部集中在 `entry/src/main/ets/`，配置只影响包名/图标/入口/页面路由。

## 6. 真机验证清单（按顺序做一遍）

| # | 验证项 | 操作 | 期望 |
|---|---|---|---|
| 1 | 安装启动 | Run 后桌面出现「屏幕方向控制」 | 应用打开，首页显示当前方向、系统自动旋转（可能为「未知」） |
| 2 | 四方向 | 依次点竖屏/横屏/反向竖屏/反向横屏 | 本应用窗口立刻按选择旋转；提示「已应用…（仅本应用窗口）」 |
| 3 | 锁定当前 | 任意方向点「锁定当前」 | 旋转后不再随设备姿态变化（在本应用内） |
| 4 | 翻转 180° | 点「翻转 180°」 | 画面上下颠倒（反向竖屏/反向横屏），再点一次翻回 |
| 5 | 跟随系统 | 点「跟随系统」 | 恢复自动旋转；转动设备时窗口跟随 |
| 6 | 悬浮球 | 设置页确认开关打开；拖动、单击 | 可拖动并记住位置；单击按「跟随 → 锁定当前 → 翻转」循环 |
| 7 | 躺姿检测 | 平躺举着平板 | 置信度上升、提示「建议锁定」；点按钮锁定本应用窗口 |
| 8 | 外部指令 | 见第 4 节 hdc 命令 | 重新拉起应用并应用对应方向 |
| 9 | 系统设置跳转 | 设置页点「打开系统『显示和亮度』」 | 跳到系统显示设置页（API 26 设备） |
| 10 | 边界 | 切到其它 App 后旋转设备 | **其它 App 行为不受本应用影响**（这是平台限制，不是 bug） |
| 11 | 重启恢复 | 设置「启动时恢复上次方向」开，锁一个方向后杀进程重开 | 启动后恢复该方向（仅本应用窗口） |

把第 2、7 项的实际结果（哪些方向枚举在目标平板上生效、躺姿阈值是否合适）记录到
[可行性评估](鸿蒙版-可行性评估.md) 第 7 节「不确定项」里，再决定是否调整。

## 7. 常见问题

| 现象 | 原因/处理 |
|---|---|
| Sync 报 `modelVersion` / `hvigorVersion` 不匹配 | 见第 5 节方案 A / B |
| 找不到 `7.0.0(26)` SDK | Settings > SDK 安装 API 26；或降低 `compatibleSdkVersion` 到设备实际版本（见下） |
| Run 灰色/提示未签名 | Project Structure > Signing Configs 勾选自动签名 |
| `hdc` 提示 no devices | 开启开发者模式与 USB 调试，`hdc kill` 后重新 `hdc start` |
| 安装报版本不兼容 | 设备 API 低于 `compatibleSdkVersion`；把 `build-profile.json5` 的 `compatibleSdkVersion` 改为 `6.0.0(20)`（鸿蒙 6）后重新构建。**注意**：只降 `compatibleSdkVersion`，编译仍要用 API 26 SDK（Project Structure 里的 compile SDK 保持 26），这样 API 26 的 `settings.openDisplaySettingsPage` 仍能编译、运行时由 `sdkApiVersion >= 26` 判断并自动降级为文字提示 |
| 点方向按钮提示「未确认生效」 | 说明调用成功但回读方向不一致：常见于自由多窗/分屏/悬浮窗（系统忽略旋转策略），或被系统旋转锁定覆盖。按提示退出多窗后重试 |
| 反向方向点击无变化 | 该方向枚举在当前平板/系统策略下不被接受，属于**待真机验证项**，请记录机型与系统版本 |
| 躺姿检测一直 0% | 平板无重力传感器，或传感器服务不可用；UI 会显示「传感器不可用」 |

## 8. 已知限制（与安卓版差异）

- **没有全局锁定**：这是鸿蒙平台限制，不是实现缺口。详见可行性评估第 0 节；
- **没有快速设置磁贴**：鸿蒙控制中心不开放三方磁贴；本工程用应用内悬浮球与桌面图标替代；
- **没有按应用规则**：无法合法获取前台应用包名；
- **悬浮球只在应用内**：跨应用悬浮窗需要系统级权限；
- **没有常驻通知**：本版未实现（如需可加，但作用仍是拉起本应用，不是全局控制）。

## 9. 产物与目录

- 构建产物：`entry/build/default/outputs/default/entry-default-signed.hap`
- 源码入口：
  - `entry/src/main/ets/entryability/EntryAbility.ets`：Want 指令解析；
  - `entry/src/main/ets/core/`：契约、后端、显示状态、偏好、躺姿引擎；
  - `entry/src/main/ets/pages/Index.ets`：三 Tab 界面与悬浮球。
- 系统签名版参考：`harmony/LazyRotate/docs/SystemRotationBackend.example.ets`（不参与默认构建）。
